# График отпусков

Внутреннее веб-приложение: сотрудники планируют отпуск на год, руководители
согласуют. Главная ценность — выявление пересечений отпусков у сотрудников
со схожими функциями через теги с лимитом одновременного отсутствия.
Масштаб: 100–500 человек, до 5 уровней иерархии.

**Документация в `docs/` — источник истины.** Прочитай `docs/README.md` перед
первой задачей. При расхождении документа и кода верен документ.

## Архитектура и стек

API-first модульный монолит: тонкий SPA-клиент, единый REST API, один серверный
процесс с модулями по границам предметной области, одна база данных.
Обоснование — `docs/01-adr-001-architecture.md`.

Django + DRF, React + TypeScript, PostgreSQL, Docker — `docs/02-adr-002-stack.md`.
Библиотеки за пределами ADR-002 не добавлять без вопроса.

Модули бэкенда (Django-приложения) по ADR-001: `employees` (сотрудники,
оргструктура, теги и лимиты), `company` (календарь праздников, настройки,
брендирование), `schedule` (график, правила, регистры, согласование,
уведомления в ленте), `audit` (журнал изменений).

## Структура репозитория

```
backend/            Django-проект, по одному приложению на модуль
frontend/           Vite + React + TypeScript
docs/               документация и задания (docs/tasks/)
docker-compose.yml  backend, frontend, postgres
```

## Границы релиза 1

Входит: загрузка сотрудников и календаря из CSV, планирование отпуска со всеми
блокирующими проверками, теги и лимиты пересечений, согласование, аудит,
базовое брендирование, вход по приглашению.

Не входит: загрузка графика из CSV (долгосрочный бэклог), экспорт, сверхурочные
часы, мобильное приложение. Полный список — `docs/07-mvp-scope.md`.

**Не добавляй функциональность за пределами текущего задания.** Если задача
кажется неполной без соседней — спроси, не делай.

## Правила работы

- Ветки `feature/*`, всё через Pull Request в `main`; прямых коммитов в `main` нет.
- Коммиты `тип: описание на русском` (`feat:`, `fix:`, `docs:`, `test:`,
  `chore:`, `refactor:`). В теле — зачем, а не что: что видно из diff.
  Коммиты небольшие, по одному изменению.
- PR описывается для не-разработчика: что сделано, как проверить, какие
  решения приняты и почему.
- **При противоречии в документах или неясности — остановись и спроси.**
  Расхождения в комплекте уже находили, они перечислены в `docs/README.md`.
- Секреты не коммитить; настройки через переменные окружения, образец
  в `.env.example`.
- Пороги правил (28, 14, 7 дней), длина рабочего дня, число уровней
  согласования — данные в справочниках, а не константы в коде.
- Бизнес-логика живёт на сервере в единственном экземпляре: фронтенд
  не повторяет расчёты, а вызывает проверку через API.
