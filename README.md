# График отпусков

[![CI](https://github.com/DGordeenko/vacation-planner/actions/workflows/ci.yml/badge.svg)](https://github.com/DGordeenko/vacation-planner/actions/workflows/ci.yml)

Веб-приложение для планирования и согласования отпусков, работы в выходные
и сверхурочных. Сотрудники вносят график на год, руководители согласуют
по цепочке, а система проверяет нормы ТК РФ и правила компании и не даёт
взаимозаменяемым сотрудникам уйти в отпуск одновременно.

Рассчитано на компанию от 100 до 500 человек и оргструктуру до 5 уровней.

**Демо:** [vacation-planner-production-ab44.up.railway.app](https://vacation-planner-production-ab44.up.railway.app).
Это вымышленная компания на 157 человек. Вход без пароля: выберите роль — сотрудник,
руководитель, HR или администратор. Например, попробуйте взять отпуск
на 12–18 июля.

---

## Зачем

Пятница, 18:40, июль. Сбой на дежурстве, а оба дежурных в отпуске:
заменить некому. В таблице такое пересечение замечают слишком поздно.

Здесь у сотрудников есть **теги** («Дежурная смена», «Касса», «Доступ в ЦОД»),
а у тега — **лимит одновременного отсутствия**. Второй отпуск сверх лимита
не сохранится ещё при планировании, а сотрудник сразу увидит, кто из коллег
уже в отпуске в эти дни, чтобы договориться о переносе.

## Возможности по ролям

**Сотрудник**
- График на год на одном экране: период выделяется мышью, проверка идёт
  до сохранения.
- Остаток дней на любую дату, годовая норма и непрерывный отпуск видны сразу.
- Отгулы за работу в выходные, внеплановые отсутствия, сверхурочные
  (оплата по закону или часы на отгул).
- Лента уведомлений и почта.

**Руководитель**
- Экран «Требует решения»: графики, исключения, отгулы и сверхурочные,
  которые ждут его подписи; цепочка согласования видна целиком.
- Календарь команды с фильтром по тегу: дни, где лимит исчерпан,
  видны сразу. Лимит считается по всей компании.
- **Теги:** назначает теги сотрудникам своей структуры, создаёт свои теги
  с лимитом, меняет и удаляет созданные им.
- Вносит отсутствия и сверхурочные за подчинённых.

**HR-администратор**
- Видит всё, ничего не меняет: графики, отгулы, отсутствия, РВД,
  календарь команды, теги, журнал изменений.
- Отчёт о сверхурочных к оплате в CSV.

**Администратор**
- Загрузка сотрудников и оргструктуры из кадровой выгрузки (CSV) с предпросмотром
  и ссылками-приглашениями.
- Все теги и лимиты, календарь праздников, работа в выходные.
- Настройки без программиста: нормы, пороги правил, длина рабочего дня,
  уровни согласования, брендирование. Изменения действуют с выбранного месяца,
  история сохраняется.
- Журнал изменений по всем ключевым данным.

## Что проверяет система

Пороговые значения — данные, а не код: норма 28 дней или длина непрерывного
отпуска меняются настройкой.

- Годовая норма, непрерывная часть отпуска не меньше 14 дней, длительный
  отпуск, перерасход накопленных дней.
- Праздник внутри отпуска не списывается с баланса и продлевает отпуск.
- Отпуск на стыке лет делится по годам для нормы и остаётся непрерывным
  для правила о двух неделях.
- Отпуск без выходных («Пн–Пт») не проходит.
- Лимиты одновременного отсутствия по каждому тегу сотрудника.
- Пределы сверхурочных; индивидуальная норма и норма с середины года.
- Перевод между отделами, вершина оргструктуры, увольнение с остатком дней.

Нарушение не обязательно блокирует: часть правил допускает исключение
с подтверждением руководителя и обязательным комментарием.

## Безопасность и защита данных

Приложение хранит персональные данные сотрудников, поэтому:

- **TLS** до базы с проверкой сертификата (`sslmode=verify-full`), HTTPS-заголовки
  и защищённые cookies, CSP и другие заголовки безопасности в nginx.
- **Админка Django** закрыта снаружи, доступ — по списку адресов.
- **Вход:** ограничение попыток, адрес клиента нельзя подделать заголовком;
  доменный вход через Kerberos и Keycloak.
- **Секреты** — из сервиса секретов облака или из файлов; пароль первого
  администратора удаляется после первого входа.
- **Журналы** в JSON, без персональных данных и токенов.
- **Контейнеры** не от root, с файловой системой только для чтения; образы
  закреплены по digest.
- **Резервные копии** шифруются ключом, который хранится вне облака,
  и выгружаются в хранилище с шифрованием KMS.
- **CI** на каждый PR: сканирование уязвимостей образов и зависимостей,
  поиск секретов в истории, `manage.py check --deploy`.

Подробно — [`docs/20-deploy-cloud.md`](docs/20-deploy-cloud.md).

## Быстрый старт (Docker)

Нужен Docker с плагином Compose.

```bash
git clone https://github.com/DGordeenko/vacation-planner.git
cd vacation-planner
cp .env.example .env          # задайте SECRET_KEY — без него бэкенд не запустится
docker compose up --build
```

Приложение откроется на **http://localhost:8080**. Поднимутся PostgreSQL, бэкенд,
фронтенд и сервис резервного копирования; миграции применяются при старте.

```bash
curl http://localhost:8080/api/health/      # {"status":"ok","database":"ok"}
docker compose down                          # остановить (-v — удалить базу)
```

- **Первый администратор.** Задайте `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`
  до первого запуска, а после первого входа удалите их
  ([`docs/14-initial-admin.md`](docs/14-initial-admin.md)).
- **Демо-режим.** `DEMO_MODE_ENABLED=True` добавит на экран входа кнопку
  «Демо-режим»: вымышленная компания в отдельной базе, ежедневный сброс
  ([`docs/15-demo-mode.md`](docs/15-demo-mode.md)).
- **Админка Django** локально: `ADMIN_ALLOW_CIDRS=0.0.0.0/0` в `.env`.

| Площадка | Как | Инструкция |

## Разработка

```bash
# Бэкенд: SQLite, если не задан DATABASE_URL
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python manage.py migrate
DEBUG=True python manage.py seed_demo   # учётные записи с паролем demo12345
python manage.py runserver              # http://localhost:8000

# Фронтенд, в отдельном терминале: /api проксируется на бэкенд
cd frontend && npm install && npm run dev   # http://localhost:5173
```

`seed_demo` создаёт оргструктуру, праздники, теги и учётные записи
`user1@demo.ru`, `manager@demo.ru`, `admin@demo.ru` в **рабочей** базе,
поэтому при `DEBUG=False` команда не запускается.

### Проверки

```bash
cd backend && ruff check . && python manage.py test         # 551 тест
cd frontend && npm run lint && npx tsc -b && npm run build
```

CI на каждый PR выполняет эти проверки и ещё:
- тесты на PostgreSQL и проверку несозданных миграций;
- `check --deploy`;
- сборку всех образов, их сканирование Trivy и SBOM;
- запуск через docker compose, проверку заголовков и журналов;
- открытие интерфейса в браузере;
- снятие и расшифровку резервной копии;
- запуск с файловой системой только для чтения;
- pip-audit, npm audit, gitleaks, actionlint, shellcheck;
- проверку манифестов Kubernetes и логики выкатки.

Зависимости обновляет Dependabot. Правила работы с репозиторием —
[`CLAUDE.md`](CLAUDE.md).
