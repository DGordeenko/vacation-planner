# ADR-002: Технологический стек

**Статус:** Принято
**Связано с:** ADR-001 (архитектурный подход)

---

## 1. Контекст

Код приложения будет писать Claude (в чате / Claude Code), а не штатная команда разработчиков. Принятого корпоративного стандарта стека или места размещения (хостинга) на момент решения нет.

Из этого вытекают дополнительные критерии к выбору стека, помимо заявленных в ADR-001 (понятность, экономность, сопровождаемость, современность, готовность к мобильному приложению):

- технология должна быть максимально распространённой — это повышает надёжность кода, генерируемого языковой моделью, и упрощает поиск специалиста "на подстраховку" в будущем;
- код должен быть читаемым для человека без активного опыта программирования, который будет проверять и принимать результат;
- решение по хостингу ещё не принято — стек не должен создавать зависимость от конкретного облачного провайдера или, наоборот, от локальной инфраструктуры.

## 2. Принятое решение

| Слой | Технология |
|---|---|
| Бэкенд | Python + Django + Django REST Framework |
| Фронтенд | React + TypeScript (SPA) |
| База данных | PostgreSQL |
| Упаковка | Docker-контейнеры |

## 3. Обоснование

- **Python/Django** — один из самых читаемых языков программирования и один из самых распространённых веб-фреймворков в мире, что даёт две выгоды одновременно: языковая модель генерирует для него особенно надёжный, хорошо протестированный сообществом код, а сам код остаётся понятным при чтении человеком без глубокого опыта в разработке.
- Django поставляется "с батарейками": встроенные аутентификация, ORM для работы с базой данных, защита от типовых уязвимостей, готовая административная панель — это закрывает часть требований к MVP (регистрация пользователя, справочники праздников/тегов/лимитов) без написания кода с нуля.
- Django-приложения (`apps`) естественно ложатся на модульное деление, зафиксированное в ADR-001: Пользователи, Отпуска, Календарь, Теги — каждый модуль как отдельное Django-приложение внутри одного монолита.
- **React + TypeScript** — самый массовый стек для SPA, с наибольшим количеством готовых компонентов (таблицы, календари, формы), что особенно важно для интерфейса графика отпусков. TypeScript снижает число ошибок за счёт проверки типов.
- **PostgreSQL** — бесплатная, надёжная, отраслевой стандарт реляционная СУБД, одинаково хорошо работающая в облаке и на собственном сервере.
- **Docker** — упаковка приложения в контейнер снимает вопрос выбора хостинга с текущей повестки: контейнер запускается идентично в облаке любого провайдера или в собственном ЦОД компании, решение о размещении можно принять независимо и позже.

## 4. Последствия

- Стек не привязывает решение к конкретному облачному провайдеру или конкретной инфраструктуре — вопрос хостинга остаётся открытым и не блокирует начало разработки.
- Готовая админ-панель Django может закрыть часть интерфейса администратора (управление справочниками) без отдельной разработки экрана на React — это стоит учитывать на этапе проектирования интерфейсов.
- При появлении принятого корпоративного стандарта стека (например, если в компании фактически принят .NET или Java) решение может быть пересмотрено — при условии, что архитектурные границы из ADR-001 сохраняются.

## 5. Вне рамок этого решения

- Конкретный провайдер хостинга и конфигурация серверов.
- CI/CD-процесс и инструменты автоматического развёртывания.
