# Отчёт о тестировании импорта кадровой выгрузки

**Дата:** сентябрь 2026
**Что проверялось:** загрузка сотрудников и оргструктуры из CSV
**Реальная выгрузка:** не предоставлена (файл не прикрепился) — тестирование выполнено на синтетических наборах, воспроизводящих типовые дефекты кадровых выгрузок

---

## 1. Главная находка: подчинение через ветвь дерева

**Суть проблемы.** Кадровая выгрузка описывает подчинение персонально: «сотрудник 1005 подчиняется сотруднику 1001». Модель данных хранит руководителя у оргединицы (см. ADR-001: оргструктура — строгое дерево). Перевод одного в другое возможен не всегда.

**Пример из тестового набора:**

```
Абдрашитов:  Группа АРМ ← Отдел поддержки ← Инфраструктура ← Дивизион ИТ
Пизик:                    Отдел ЦОД       ← Инфраструктура ← Дивизион ИТ
```

Абдрашитов подчиняется Пизику, но они в разных ветвях. Подъём вверх по дереву от Абдрашитова проходит мимо Отдела ЦОД, и руководитель **теряется молча**.

**Почему это критично.** Сотрудник без руководителя — это сотрудник без согласующего. Его график невозможно утвердить. При загрузке 100–500 человек такие случаи потерялись бы незаметно и всплыли бы в разгар кампании.

**Что сделано.** Добавлена проверка: после построения дерева система сверяет выведенное подчинение с заявленным в файле. Расхождение — ошибка, файл не применяется, в сообщении указано, какую строку править.

**Что требуется от вас.** Когда придёт реальная выгрузка, эта проверка покажет, сколько в ней подчинений через ветвь. Возможны три исхода:
1. Таких случаев нет — работаем как есть.
2. Единичные случаи — правятся в выгрузке вручную.
3. Массовые случаи — значит, в компании принято матричное подчинение, и модель «строгое дерево» из ADR-001 требует пересмотра. Это решение стоит принять до начала кампании, а не во время.

**Решение (ноябрь 2026):** оргструктура остаётся строгим деревом. Подчинение через ветвь правится в выгрузке; пересмотр модели не планируется.

---

## 2. Вторая находка: потеря руководителей при построении дерева

**Суть.** Первая версия импорта присваивала руководителя оргединице по последней строке файла, где эта оргединица упоминалась. При нормальной иерархии (начальник отдела → тимлид → инженеры) это давало неверный результат: тимлид становился руководителем группы, а начальник отдела терял свою роль, и **тимлид оставался без руководителя**.

**Что сделано.** Правило вывода переписано: руководителем оргединицы становится тот, кого называют её сотрудники **и кто сам состоит в этой же оргединице**. Если названный руководитель сидит выше по структуре, оргединица остаётся без собственного руководителя — поиск поднимется к родителю.

**Проверено:**

| Сотрудник | Оргединица | Руководитель |
|---|---|---|
| Начальник Отдела | Отдел Т | — (вершина) |
| Тимлид Группы | Группа Т | Начальник Отдела |
| Инженер Первый | Группа Т | Тимлид Группы |
| Инженер Второй | Группа Т | Тимлид Группы |

Видимость данных выстроилась соответственно: начальник видит 4 человек, тимлид — 3, инженеры — только себя.

## 3. Устойчивость к форматам выгрузок

Кадровые системы выгружают данные по-разному. Импорт распознаёт:

| Что | Поддержано |
|---|---|
| Разделитель | `;`, `,`, табуляция — определяется автоматически |
| Кодировка | UTF-8, UTF-8 с BOM, CP1251 |
| Заголовки | английские (`employee_number`) и русские (`Таб_номер`, `ФИО`, `Дата_приема`, `Руководитель`, `Остаток`) |
| Форматы дат | `2027-01-15`, `15.01.2027`, `15/01/2027`, `15-01-2027`, `2027/01/15` |
| Десятичный разделитель | точка и запятая (`12,5` = `12.5`) |

Порядок строк значения не имеет: руководитель может идти в файле ниже подчинённого.

## 4. Отклоняемые дефекты

Файл применяется **целиком или не применяется вовсе**. При любой ошибке не сохраняется ничего, а пользователь получает построчный список проблем.

| Дефект | Сообщение |
|---|---|
| Пустой табельный номер / ФИО / email | указывается строка и колонка |
| Email без `@` | показывается значение |
| Нераспознанная дата приёма | показывается значение |
| Дублирующийся табельный номер или email | указывается строка первого вхождения |
| Руководитель не найден ни в файле, ни в базе | показывается номер |
| Сотрудник — руководитель самого себя | — |
| Циклическое подчинение (А→Б→А) | — |
| Отрицательный остаток отпуска | — |
| Дата увольнения раньше даты приёма | — |
| Подчинение через соседнюю ветвь | см. раздел 1 |
| Нет обязательных колонок | перечисляются недостающие |

**Предупреждения** (не блокируют загрузку): не указан остаток отпуска, дата приёма в будущем, в одной оргединице несколько кандидатов в руководители.

## 5. Прочее проверенное поведение

- **Повторная загрузка обновляет, а не дублирует.** Ключ — табельный номер. Изменённые ФИО и оргединицы применяются, количество сотрудников не растёт.
- **Предпросмотр (dry-run).** Файл проверяется без записи в базу — для экрана загрузки, где пользователь видит проблемы до применения.
- **Оргструктура создаётся из файла** — дивизион, подразделение, отдел, группа собираются в дерево по колонкам.
- **Теги.** По оргединице присваивается автоматически, из колонки `extra_tags` — вручную. Источник фиксируется, поэтому при переводе сотрудника автоматический тег пересчитается, а ручные сохранятся.
- **Начальный остаток** попадает в регистр отпускных дней как запись с причиной «начальная миграция».
- **Приглашения.** Каждому созданному сотруднику выдаётся токен для входа по ссылке — самостоятельная регистрация не требуется.
