# Настройка почтовых уведомлений

## 1. Как устроено

Письма **не отправляются прямо в запросе**: недоступный SMTP не должен
ронять сохранение графика или согласование. События кладутся в очередь
(`OutgoingEmail`), отправкой занимается отдельная команда по расписанию.

Очередь заполняется автоматически по факту уведомления в ленте, поэтому
почта и лента не расходятся между собой.

## 2. Что попадает в письма

| Событие | Как отправляется |
|---|---|
| Требуется согласование графика | Сразу |
| Требуется подтверждение исключения | Сразу |
| Превышен лимит одновременного отсутствия | Сразу |
| Решение по вашей заявке | Дневной сводкой |

Логика простая: то, что требует действия получателя, уходит немедленно;
то, что информирует, копится и приходит одним письмом.

Каждое письмо содержит ссылку на нужный экран и оформлено в фирменных
цветах компании из настроек.

## 3. Включение

```python
MAIL_NOTIFICATIONS_ENABLED = True
APP_BASE_URL = "https://vacation.corp.ru"   # для ссылок в письмах
DEFAULT_FROM_EMAIL = "vacation@corp.ru"

EMAIL_HOST = "smtp.corp.ru"
EMAIL_PORT = 587
EMAIL_HOST_USER = "vacation"
EMAIL_HOST_PASSWORD = "<из переменных окружения>"
EMAIL_USE_TLS = True
```

Пароль хранится в переменных окружения, а не в репозитории.

Пока `MAIL_NOTIFICATIONS_ENABLED` выключен, очередь не заполняется вовсе —
письма не копятся «про запас».

## 4. Расписание отправки

```bash
# Срочные — каждые несколько минут
*/5 * * * * cd /opt/vacation/backend && python manage.py send_mail_queue

# Сводка — раз в день утром
0 9 * * 1-5 cd /opt/vacation/backend && python manage.py send_mail_queue --digest
```

Команда сама проверяет, включён ли модуль, и ничего не делает, если выключен.

## 5. Поведение при сбоях

- Письмо остаётся в очереди и повторяется до 5 попыток: временная
  недоступность SMTP не теряет уведомление.
- После исчерпания попыток письмо помечается как ошибочное и больше
  не повторяется, текст ошибки сохраняется.
- Сбой сводки не портит уже отправленные письма других получателей.

Посмотреть застрявшие письма:

```python
OutgoingEmail.objects.filter(status="failed").values(
    "recipient_email", "subject", "last_error")
```

## 6. Отказ от писем

Сотрудник отключает уведомления в настройках профиля
(`PATCH /api/v1/auth/me/` с полем `email_notifications_enabled`).

Отказ фиксируется явно: письмо создаётся со статусом «пропущено», а не
просто не появляется. Иначе потом невозможно выяснить, почему уведомление
не пришло — человек отказался или система не сработала.

Уведомления в ленте приложения продолжают приходить в любом случае.

## 7. Проверка перед запуском

Отправить пробное письмо без настоящего SMTP:

```bash
python manage.py shell -c "
from django.core.mail import send_mail
send_mail('Проверка', 'Текст', None, ['you@corp.ru'])"
```

При `EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'`
письмо выведется в консоль — удобно для проверки шаблонов до подключения
реального сервера.
