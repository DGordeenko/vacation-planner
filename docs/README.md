# Документация проекта

Приложение для сбора данных и подготовки графика отпусков.
Масштаб: 100–500 сотрудников, до 5 уровней иерархии, одна компания, один регион.

Документы ниже — источник истины. При расхождении между документом и кодом
верен документ; при расхождении между документами — остановиться и спросить
(см. `../CLAUDE.md`).

## Для нового участника

Минимальный путь: `00` → `07` (что делаем и в каком объёме) → `01`, `02`
(как построено) → `03`, `04` (данные и логика) → `05`, `06` (интерфейсы) →
`08` (как проверяем).

Перед написанием кода обязательны `04-algorithms.md` и `08-acceptance-scenarios.md`:
первый содержит решения по краевым случаям, которые иначе будут приняты
произвольно, второй — конкретные числа, по которым принимается работа.

## Открытые вопросы

Требуют решения владельца проекта. Пока ответа нет, принятые предположения
указаны в скобках — они реализованы именно так.

| № | Вопрос | Принятое предположение | Где зафиксировано |
|---|---|---|---|
| 1 | Порядок согласования правок графика для сотрудников у вершины оргструктуры | Цепочка дополняется администратором до двух подписей | ФЗ, п. 7.1 |
| 2 | Правило о захвате выходных обобщено: блокируется любой отпуск без субботы и воскресенья, а не только блок Пн–Пт | Обобщённая формулировка | ФЗ, п. 7.4; отчёт, п. 5.2 |
| 3 | Индивидуальная норма отпуска (увеличенная для отдельных категорий) | Норма глобальная; поле переопределения заложено, но не используется | ФЗ, п. 7.5 |
| 4 | Точный формат и шаблон экспорта графика | Вынесен за рамки релиза 1 | ФЗ, п. 7.2 |
| 5 | Настройки компании не версионируются во времени | При изменении нормы история прошлых лет пересчитается по новому значению | Отчёт, п. 5.1 |
| 6 | Поведение при одновременном редактировании графика несколькими руководителями | Не определено; при 100–500 пользователях риск признан низким | Отчёт, п. 5.5 |
| 7 | Учитывать ли отгулы в лимитах одновременного отсутствия по тегам | Учитываются (отгул — такое же отсутствие, как отпуск) | Решение принято при реализации |
| 8 | Сколько в реальной кадровой выгрузке подчинений «через ветвь» | Не проверено: реальная выгрузка не предоставлена | `10-import-test-report.md`, разд. 1 |

**Вопрос 8 — самый срочный.** Оргструктура в модели данных — строгое дерево.
Если в реальной выгрузке окажется много подчинений через соседнюю ветвь
(сотрудник в одном отделе, руководитель в другом), модель потребует пересмотра.
Менять её дешевле до кампании планирования, чем во время.
