# Этапы реализации релиза 1

Черновой порядок. Детальные задания пишутся перед началом каждого этапа.
Границы определены в `docs/07-mvp-scope.md`.

Порядок подчинён одному правилу: сначала сквозной путь через все слои,
потом реальные данные, и только потом — правила, которые на этих данных
можно проверить.

---

**00. Каркас проекта** — готово к выдаче, см. `00-skeleton.md`.
Структура, контейнеры, CI, проверка связи между фронтендом и бэкендом.

**01. Сквозной срез** — вход по приглашению, годовой календарь, внесение
отпуска, одна проверка, сохранение. Один сценарий целиком, от интерфейса
до базы: даёт увидеть систему в работе до того, как написана основная масса кода.

**02. Модель данных и справочники** — сущности из `03-data-model.md`,
справочник правил с порогами, настройки компании, аудит изменений.
Аудит включается здесь, а не в конце: историю невозможно восстановить задним числом.

**03. Загрузка сотрудников и оргструктуры** — импорт CSV транзакцией
с предпросмотром, автоматические теги по оргструктуре, учётные записи
с приглашениями. Первый этап, где нужны реальные данные из кадрового учёта.

**04. Календарь праздников** — административная панель: годовая сетка,
загрузка CSV, перенос года, предупреждение о последствиях правок.

**05. Расчёты и блокирующие проверки** — накопление дней, праздники и продление,
отпуск на стыке лет, годовая норма, непрерывность, потолок дней, захват выходных.
Основа всей предметной логики; краевые случаи уже решены в `04-algorithms.md`.

**06. Теги и лимиты пересечений** — сводный календарь команды с фильтром
по тегу, блокировка при превышении лимита. Главная ценность продукта.

**07. Согласование графика** — цепочка через четыре уровня, подтверждение
исключений с комментарием, отклонение, отзыв, лента уведомлений.

**08. Интерфейс сотрудника** — годовой календарь, показатели готовности
графика, карточка проверки до сохранения, брендирование под компанию
по `06-ux-branding.md`.

**09. Интерфейс руководителя** — лента «Требует моего решения» со счётчиком,
календарь команды, экраны согласования.

**10. Приёмка** — прогон 33 сценариев из `08-acceptance-scenarios.md`,
пилот на одном отделе, **сверка остатков отпускных дней с кадровым учётом**.

---

Сверка остатков на пилоте — не функция системы, но обязательное условие
запуска: расхождение в исходных остатках обесценивает все расчёты.

## После релиза 1

Актуализация утверждённого графика, отгулы за работу в выходные дни,
внеплановые отсутствия, доменная аутентификация, почтовые уведомления,
экспорт графика, сверхурочные часы.

Загрузка графика отпусков из CSV — в долгосрочном бэклоге, не планируется.
